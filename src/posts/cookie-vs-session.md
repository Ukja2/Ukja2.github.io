HTTP는 상태를 기억하지 않는(stateless) 프로토콜이라, 로그인 상태를 유지하려면 어딘가에 정보를 저장해야 한다.

## 쿠키

- **브라우저(클라이언트)** 에 저장됨
- 서버가 응답에 `Set-Cookie` 헤더를 담아 보내면, 이후 요청마다 브라우저가 자동으로 같이 보냄
- 용량이 작고(4KB 안팎), 클라이언트에 그대로 노출되므로 민감한 정보를 직접 담기엔 부적합

## 세션

- 실제 데이터는 **서버**에 저장됨
- 클라이언트는 그 데이터를 찾기 위한 **세션 ID**만 쿠키로 들고 있음
- 서버가 그 ID로 저장소(메모리, Redis 등)를 조회해서 사용자 정보를 확인

## 정리

| | 쿠키 | 세션 |
| --- | --- | --- |
| 저장 위치 | 클라이언트 | 서버 |
| 보안 | 상대적으로 취약 | 상대적으로 안전 |
| 서버 부담 | 없음 | 저장소 필요 |

요즘은 서버 확장성을 위해 세션 대신 **JWT** 같은 토큰 방식도 많이 쓰지만, "클라이언트 vs 서버 중 어디에 진짜 데이터를 두는가"의 기본 개념은 같다.
