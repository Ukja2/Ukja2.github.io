인덱스는 책의 "찾아보기"와 같다. 처음부터 끝까지 훑는 대신, 정렬된 목차를 보고 바로 위치를 찾아간다.

## 인덱스가 없으면

```sql
SELECT * FROM users WHERE email = 'a@example.com';
```

인덱스가 없으면 DB는 테이블 전체를 한 줄씩 다 확인하는 **풀 스캔**을 한다. 데이터가 많아질수록 느려진다.

## 인덱스를 걸면

```sql
CREATE INDEX idx_users_email ON users(email);
```

`email` 컬럼 값을 정렬된 트리(보통 B-Tree) 구조로 따로 저장해둬서, 검색할 때 트리를 타고 내려가며 훨씬 빠르게 찾는다.

## 공짜가 아니다

- **쓰기(INSERT/UPDATE/DELETE)가 느려진다** — 데이터가 바뀔 때마다 인덱스도 같이 갱신해야 하기 때문.
- **저장 공간을 더 쓴다** — 인덱스 자체도 별도 자료구조라 디스크를 차지한다.

그래서 조회는 자주 하지만 쓰기는 드문 컬럼(예: 로그인 이메일, 검색 조건으로 자주 쓰는 컬럼)에 우선적으로 인덱스를 거는 게 좋다.

## 정리

인덱스 = 조회 속도 ↑ 대신 쓰기 속도 ↓, 저장 공간 ↑. 아무 컬럼에나 걸기보다 실제 쿼리 패턴을 보고 결정해야 한다.
