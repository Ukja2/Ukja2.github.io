## 망분리(Network Separation)란

**업무용 내부망과 인터넷(외부망)을 물리적 또는 논리적으로 완전히 분리해서, 인터넷을 통한 보안 위협이 업무 시스템에 도달하지 못하게 하는 방식**이다.

인터넷에 연결된 PC는 악성코드, 피싱, 해킹 시도 등에 항상 노출돼 있다. 업무 시스템(고객 정보, 금융 거래 데이터, 내부 문서 등)이 그 PC와 같은 네트워크에 있으면, PC 한 대만 뚫려도 업무 시스템 전체가 위험해진다. 망분리는 이 연결 경로 자체를 끊어서, 인터넷 쪽에서 무슨 일이 생기든 업무망에는 애초에 닿을 수 없게 만든다. 국내 금융권·공공기관에서는 법적으로 의무화된 경우가 많다.

## 실제 구조: 네트워크가 두 개로 나뉜다

물리적 망분리를 하면 회사 안에 완전히 분리된 두 개의 네트워크가 생긴다.

```
[업무망]  ── 사내 서버, 사내 메신저, 내부 DB, 프린터 등 (인터넷 연결 X)
[인터넷망] ── 인터넷 전용 PC, 웹서핑, 외부 메일 등 (업무망과 연결 X)
```

- **업무망 내부 통신은 정상 작동한다**: 사내 서버 접속, 파일 공유, 사내 메신저, 결재 시스템 같은 건 업무망 자체가 하나의 완결된 LAN이라 아무 문제 없이 동작한다. 이 LAN에 그냥 **인터넷으로 나가는 문이 없을 뿐**이다.
- **인터넷이 필요하면 다른 망(다른 PC)에서**: 웹서핑, 외부 메일, 자료 검색처럼 인터넷이 필요한 업무는 물리적으로 완전히 분리된 인터넷 전용 PC에서 처리한다. 직원 책상에 PC가 두 대(업무용 + 인터넷용) 놓여 있는 회사를 본 적 있다면, 그게 물리적 망분리의 실제 모습이다.

## 흔한 오해: LAN 통신도 인터넷이 있어야 되는 거 아닌가?

아니다. **인터넷과 LAN 통신은 완전히 다른 층위**다.

- **인터넷**: 전 세계에 흩어진 수많은 네트워크를 서로 연결해주는 광역망(WAN). ISP가 우리 네트워크를 이 망에 연결시켜준다.
- **LAN**: 같은 건물/사무실 안에서 스위치나 공유기로 직접 연결된 로컬 네트워크. 그 안의 기기들끼리는 인터넷을 전혀 거치지 않고 통신한다.

L2 스위치에 전원을 넣고 기기들을 랜선으로 꽂기만 해도, 스위치는 각 포트에서 오가는 트래픽을 보고 MAC 주소를 자동으로 학습해서 프레임을 정확히 전달해준다. 여기에 인터넷, 공유기, ISP는 전혀 필요 없다. IP 기반 통신(핑, 파일 공유 등)을 하려면 기기들끼리 같은 대역의 IP만 맞춰주면 되는데, 이것도 고정 IP를 직접 설정하거나 사설 DHCP를 쓰면 되지 인터넷과는 무관하다.

즉 업무망은 인터넷 없이도 완전하게 동작하는 독립된 네트워크이고, 망분리는 이 업무망과 인터넷망 사이의 연결만 끊어놓은 것이다.

## 물리적 망분리 vs 논리적 망분리

| | 물리적 망분리 | 논리적 망분리 |
| --- | --- | --- |
| 구현 방법 | PC/네트워크 장비 자체를 완전히 별도로 구성 | 가상화(VDI 등)로 하나의 물리 환경 안에서 논리적으로 분리 |
| 사용자 경험 | 업무용 PC, 인터넷용 PC 두 대를 따로 사용 | PC 한 대에서 화면 전환/가상 데스크톱으로 전환 |
| 비용/공간 | 높음 (PC·회선 이중 구축) | 상대적으로 낮음 |
| 보안 수준 | 매우 높음 (물리적으로 연결 자체가 없음) | 높음 (가상화 계층이 뚫리면 위험 존재) |

## 두 망 사이에 데이터를 옮겨야 할 때는?

평소에는 두 망이 통신하지 않는다. 다만 업무상 데이터를 옮겨야 할 때를 위해 **망연계(Network Linkage) 솔루션**이라는 통제된 통로를 따로 둔다. 핵심은 두 망을 직접 잇는 게 아니라, 중간에 완충 장비를 두고 **파일 단위로 검사 후 중계**한다는 것이다.

```
[인터넷망] ──→ [망연계 장비] ──→ [업무망]
```

- 인터넷망 PC가 파일을 망연계 장비에 올린다
- 장비가 바이러스 검사, 매크로 제거, 확장자·용량 필터링 등을 거친다
- 통과한 파일만 업무망으로 전달된다

보안이 특히 중요한 곳(국방, 원전, 금융 핵심망)에서는 소프트웨어 필터링만으로 부족하다고 보고, 하드웨어 자체가 한쪽 방향으로만 신호를 흘려보내는 **데이터 다이오드**를 쓰기도 한다. 물리적으로 역방향 통신이 불가능하게 만들어서, 소프트웨어 버그가 있어도 업무망의 데이터가 인터넷 쪽으로 유출될 경로 자체가 없다.

## 전체 그림: DMZ는 어디에 속하나

DMZ와 직원용 인터넷망은 서로 목적은 다르지만(하나는 대외 서비스 제공, 하나는 직원 인터넷 사용), **둘 다 "인터넷과 연결된 쪽"에 속한다**는 공통점이 있다. 망분리가 실제로 가르는 경계는 이 "인터넷과 연결된 영역 전체"와 업무망 사이다.

```
                         [인터넷]
                            │
        ┌───────────────────┼───────────────────┐
        │                   │                   │
  (인터넷망: 직원         [방화벽1]        (회사의 대외 서비스 인프라)
   인터넷용 PC 등)            │
        │                   ▼
        │                DMZ (공개 서버들: 웹서버, 메일서버 등)
        │                   │
        └───────────────────┴─────────[방화벽2]───┘
                            │
                (인터넷 쪽 인프라는 여기서 끝)

═══════════════ 망분리 경계 (상시 연결 없음, 망연계로만) ═══════════════

                        [업무망]
              (내부 DB, 사내 서버, 업무용 PC 등 — 완전 격리)
```

- DMZ ↔ 인터넷: 상시 연결 (방화벽1로 통제)
- 인터넷망(직원용) ↔ 인터넷: 상시 연결 (일반 NAT/방화벽)
- **업무망 ↔ 위의 모든 것**: 상시 연결 없음, 필요할 때만 망연계로 파일만 이동

DMZ가 아무리 잘 격리돼 있어도 DMZ 자체는 결국 인터넷 쪽 세계에 속하는 인프라고, 업무망은 그 세계와 접점이 없는 완전히 별개의 네트워크다. 즉 DMZ와 (직원용) 외부망 연결은 각각 따로 존재하는 게 맞지만, 그 둘은 같은 편(인터넷 연결된 쪽)이고, 망분리가 나누는 선은 "그 편 전체 vs 업무망"이다.

## DMZ, VPN과 무엇이 다른가

- **DMZ**: 외부에 공개해야 하는 서버를 격리된 구역에 두고, 내부망과는 제한적으로만 연결 (완전 차단이 아니라 통제된 접근)
- **VPN**: 공용망을 거치더라도 암호화된 터널로 사설망에 접근할 수 있게 함 (안전하게 연결해준다)
- **망분리**: 애초에 업무망과 인터넷망 사이의 연결 경로 자체를 없애버림 (아예 못 만나게 한다)

셋 다 "내부의 중요한 자원을 외부 위협으로부터 보호한다"는 목표는 같지만, DMZ·VPN이 "통제된 연결"을 만드는 접근이라면, 망분리는 "연결 자체를 없앤다"는 훨씬 더 강력한 방식이다.
