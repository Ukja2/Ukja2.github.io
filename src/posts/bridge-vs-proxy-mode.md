가상머신 네트워크 설정이나 공유기 설정에서 자주 보이는 "브릿지 모드"와, 요청을 대신 처리해주는 "프록시"는 이름만 비슷하지 완전히 다른 개념이다.

## 브릿지(Bridge)란

브릿지는 **두 개의 네트워크 구간을 하나로 이어 붙여서, 마치 같은 네트워크인 것처럼 만들어주는 장치/기능**이다. OSI 7계층 중 **2계층(데이터 링크 계층)** 에서 동작하며, MAC 주소를 보고 프레임을 그대로 전달(forward)한다.

핵심은 **투명성**이다. 브릿지는 내용을 건드리지 않고 그냥 전달만 하기 때문에, 통신하는 양쪽 호스트는 중간에 브릿지가 있다는 사실 자체를 모른다.

### 예시: 가상머신의 브릿지 모드

VirtualBox나 VMware에서 네트워크 어댑터를 **Bridged**로 설정하면, 가상머신이 호스트 PC와는 별개로 **물리 네트워크(공유기)에서 직접 IP를 할당받는** 독립된 장치처럼 보인다. 반대로 NAT 모드는 호스트 뒤에 숨어서 호스트의 IP를 통해서만 외부와 통신한다.

```
[공유기] ─┬─ [호스트 PC]
          └─ [가상머신]   ← 브릿지 모드: 공유기 입장에서 별도 장치로 보임
```

## 프록시(Proxy)란

프록시는 **클라이언트와 서버 사이에서 요청을 대신 받아 처리해주는 중개자**다. 브릿지와 달리 훨씬 상위 계층(주로 애플리케이션 계층)에서 동작하고, 그냥 전달만 하는 게 아니라 **내용을 보고 판단**한다 — 캐싱, 필터링, 로깅, 인증, 로드밸런싱 등.

- **포워드 프록시**: 클라이언트 쪽에 있으며, 클라이언트를 대신해서 서버에 요청함 (사내망에서 외부 접속 제어할 때 흔히 씀)
- **리버스 프록시**: 서버 쪽에 있으며, 클라이언트는 진짜 서버가 아니라 프록시와 통신하는 줄만 앎 (Nginx가 백엔드 앞에 서는 구조가 대표적)

## 핵심 차이

| | 브릿지 | 프록시 |
| --- | --- | --- |
| 동작 계층 | 2계층 (MAC 기반) | 주로 애플리케이션 계층 |
| 내용 처리 | 그대로 전달만 함 | 내용을 보고 가공/판단 |
| 존재 인지 | 서로 모름 (투명) | 클라이언트/서버가 인지하는 경우가 많음 |
| 목적 | 네트워크를 물리적으로 확장/연결 | 요청을 중개하며 부가 기능 제공 |

한마디로: **브릿지는 "두 네트워크를 이어 붙이는 다리"**, **프록시는 "요청을 대신 처리해주는 대리인"** 이라고 생각하면 헷갈리지 않는다.
