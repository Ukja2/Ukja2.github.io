## DMZ(DeMilitarized Zone)란

**내부 네트워크(사설망)와 외부 인터넷 사이에 두는 완충 지대** 역할의 네트워크 구간이다. 외부에 공개해야 하는 서버(웹서버, 메일서버, DNS 서버 등)를 이 구간에 배치해서, 내부망을 직접 노출시키지 않으면서도 외부에 서비스를 제공할 수 있게 한다.

## 왜 필요한가

회사가 내부망만 쓰고 완전히 폐쇄하면 좋겠지만, 시스템 업데이트나 FTP, 이메일처럼 외부 네트워크와 반드시 연결돼야 하는 서비스가 생긴다. 이런 서비스를 위해 어떤 서버는 인터넷에서 접근 가능한 상태여야 하는데, 그 서버를 내부망(사설 네트워크)에 그대로 두면 서버가 해킹당했을 때 공격자가 내부망 전체(직원 PC, 내부 DB 등)로 침투할 수 있는 발판이 되어버린다.

DMZ는 이 문제를 막기 위해 **외부 공개 서버를 내부망과도, 인터넷과도 분리된 별도의 구역**에 둔다. DMZ는 "내부망 안에 있는 특수 구역"이 아니라, **내부망·DMZ·외부망이 각각 독립된 3개의 존(zone)으로 나뉜다**는 게 핵심이다.

```
인터넷 ── [방화벽1] ── DMZ(공개 서버들) ── [방화벽2] ── 내부망(사설 IP)
```

## 방화벽1과 방화벽2

"포트를 연다"는 서버(리스닝)와 방화벽(필터링)이라는 서로 다른 두 층에서 일어나는 일이다. 서버가 포트를 리스닝 중이면 출발지가 누구든 받아줄 준비가 되어 있지만, 그 패킷이 서버에 도달하려면 먼저 방화벽을 통과해야 한다. 방화벽1과 방화벽2는 이 통과 범위가 다르다.

- **방화벽1 (외부 → DMZ)**: 목적지 포트만 지정한다. 인터넷의 불특정 다수가 80/443번으로 접속하는 걸 전부 받아준다 — 출발지는 제한하지 않는다.
- **방화벽2 (DMZ → 내부망)**: 기본적으로 전부 차단(default deny)하고, 출발지 IP·목적지 IP·목적지 포트를 전부 못박은 예외 규칙만 허용한다. 예를 들어 "웹서버 A(DMZ) → DB 서버 B(내부망)의 3306번 포트"만 통과시킨다면, DB 서버가 3306을 계속 리스닝하고 있어도 웹서버 A가 아닌 다른 서버가 보낸 패킷은 방화벽2에서 걸러져 DB 서버에 도달하지도 못한다.

비유하면 DB 서버의 리스닝은 "문이 잠겨있지 않은 상태"고, 방화벽2는 "문 앞에서 신분증(출발지 IP)을 확인하고 웹서버 A만 들여보내는 경비원"이다. 문 자체는 누구에게나 열려 있어도, 경비원을 통과하지 못하면 문 앞에 도달할 수조차 없다.

즉 방화벽2는 "이 서버와 이 서버 사이에만 이 포트로 통신을 허용"하는 화이트리스트[^1] 예외다. DMZ 서버가 뚫려도 공격자가 갈 수 있는 곳은 그 예외 규칙에 못박힌 목적지 하나뿐이다. 연결도 항상 DMZ 쪽에서 먼저 요청을 보내고 내부망은 응답만 돌려주는 방향으로 열리며, 실무에서는 DMZ 웹서버가 DB에 직접 붙지 않고 중간에 애플리케이션 서버를 한 겹 더 둬서 "DMZ → 앱서버 → DB"로 완충하는 구조도 흔하다.

## 핵심 개념

| | 내부망(사설 네트워크) | DMZ | 인터넷 |
| --- | --- | --- | --- |
| 신뢰 수준 | 높음 | 중간 (공개되지만 격리됨) | 낮음 (비신뢰) |
| 배치 대상 | 직원 PC, 내부 DB | 웹서버, 메일서버, DNS 서버 | - |
| 외부 접근 | 불가 | 가능 (제한적) | - |

[^1]: 화이트리스트(whitelist): 허용할 대상만 미리 정해두고, 그 외에는 전부 차단하는 방식.
