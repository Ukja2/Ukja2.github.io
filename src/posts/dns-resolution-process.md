`example.com`을 브라우저에 입력하면 실제로는 여러 단계를 거쳐 IP 주소를 찾는다.

## 조회 순서

1. 브라우저/OS 캐시 확인
2. 로컬 DNS 리졸버(보통 ISP 제공)에 질의
3. **루트 네임서버** → `.com` 같은 **TLD 네임서버** 위치 안내
4. TLD 네임서버 → `example.com`을 관리하는 **권한 있는 네임서버** 위치 안내
5. 권한 있는 네임서버가 실제 IP 주소를 응답

## 캐싱이 중요한 이유

매번 이 전체 과정을 반복하면 느리기 때문에 각 단계마다 TTL(Time To Live)만큼 결과를 캐싱해둔다. 그래서 도메인 레코드를 바꿔도 전 세계에 반영되기까지 시간이 걸리는 것이다.

## 자주 쓰는 레코드 타입

| 타입 | 용도 |
| --- | --- |
| A | 도메인 → IPv4 주소 |
| AAAA | 도메인 → IPv6 주소 |
| CNAME | 도메인 → 다른 도메인 별칭 |
| MX | 메일 서버 지정 |
